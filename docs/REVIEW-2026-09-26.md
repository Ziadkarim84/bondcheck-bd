# BondCheck BD: feature inventory, product review and code review

Date: 2026-09-26. Scope: `backend/`, `mobile/`, `web/` as moved into ~/paddle-projects/bondcheck-bd. Nothing has been changed yet; this is for the owner to cross-check.

## 1. The core job

A prize-bond holder wants one answer: **"Did any of my bonds win, and what do I do now?"**

What we know about the use:
- Draws happen 4 times a year. Each draw has about 46 winning numbers (1st 1, 2nd 1, 3rd 2, 4th 2, 5th 40), and as far as I know they apply to every series. Please confirm this, because it changes what the app needs to store.
- Prizes can be claimed for 2 years, so every bond has to be checked against the last 8 draws.
- Families often hold many bonds, often in consecutive runs. Bonds are entered once and then the app is idle for three months at a time.

So the ideal app is: add your bonds once, get told when you win, see what to do. Everything else is secondary.

## 3. The big decision: do we need accounts and a server database of users?

Today every user must register, and all bonds live in a MySQL database on Railway. That backend is **down right now**, so the app can't be used at all.

Because a draw has only about 46 winning numbers, the phone can do the checking itself:

**Recommended: local-first**
- Bonds are stored on the phone. No registration, no login.
- A tiny public file (for example `results.json` with the last 8 draws) is updated automatically after each draw. It can be hosted for free on the web page from #28.
- The app downloads that file and checks the bonds on the phone, in milliseconds.
- Notifications: after each draw the server sends one push to everyone ("Draw 123 results are out"), and the app checks and shows "You won" or "No wins this time". Or the phone checks by itself in the background.
- Backup: a free export/import file, and Android's automatic backup.

**What we gain**
- The first launch goes straight to "add your bonds".
- No passwords, OTP emails or personal data, so the Play Data safety form becomes easy.
- Nothing to keep running except a scheduled job and a static file.
- Railway costs drop to about zero, and a server outage can't break the app.

**What we give up**
- Cross-device sync; backup/restore covers phone changes.
- Per-user email alerts.
- Server-side statistics on how many bonds people track.

**Alternative:** keep accounts but make them optional ("sign in to back up"). That's more work, and I don't think it earns its keep for this app.

## 4. Code-review findings (current code)

**Blocking**
1. The backend is offline (Railway "Application not found"). The app can't log in or load anything.
2. `app.json` requests `RECORD_AUDIO`, which is never used. Play reviewers flag unexplained sensitive permissions. Remove it.
3. Premium is advertised with prices, but tapping it shows "Coming soon". Play can treat a paywall that doesn't work as misleading.

**Bugs**
4. Bonds added through scanning are never checked against past draws. Manual and range adds call `checkBondAgainstAllResults`; OCR confirm doesn't.
5. The free limit is shown as 50 on the paywall, but 25 (+ referrals) is enforced.
6. Token lifetimes are inverted: the access token lasts 30 days and the refresh token only 7.
7. Draw dates are computed from fixed calendar dates (Jan 31, Apr 30…). If Bangladesh Bank holds a draw on another day, the countdown and dates are wrong. The PDF has the date; it should be read from there.
8. The home ad gate re-locks results every time the screen remounts, and it unlocks without an ad if none loaded. It's inconsistent either way.

**Security** (moot if accounts are cut, serious if kept)
9. OTP has no rate limit and no attempt limit: anyone can email-bomb an address or brute-force a 6-digit code.
10. The admin API is protected only by a shared header secret, with no rate limit.
11. The CORS check uses `startsWith`, so `https://bondcheckbd.vercel.app.evil.com` passes.

**Quality**
12. Emoji are used as tab and section icons, and there's no design system (colours and sizes hard-coded per screen).
13. Many user-facing strings are English-only.
14. The support email is `support@bondcheckbd.com`, a domain we don't appear to own.
15. The EAS build error (expo-router plugin) is still unresolved, and the version is hard-coded as 1.0.0 in Settings.
16. Range add does up to 1,000 sequential upserts plus match checks in one request, which is slow and can time out.

## 6. Decisions and facts confirmed (2026-09-26)

**Monetization (owner approved)**
- Free: up to 30 bonds, full win checking for every claimable draw, alerts, banner ads on list/results screens.
- Rewarded ads: each watch permanently adds 3 bond slots, up to 60 total (owner decision). The user chooses to watch.
- Pro: one-time Google Play purchase, ~৳199–299, gives unlimited bonds, no ads and backup to file. Buyers need a card or a Play gift card; direct bKash for digital unlocks would break Play billing policy.
- Never gate the win result behind an ad. At most one interstitial per session, after adding bonds, never on results.
- This replaces feature #11 "Cut": the free limit stays, but generous and earnable. Referrals (#22) stay cut.

**Public results website with AdSense (owner approved)**
- Replaces the web app (#28): one page per draw + number checker + Play link + privacy policy. SEO for the quarterly search spike; competitors exist (e.g. prizebondinfo.com and result portals), so expect a slow build.

**Facts checked**
- One common set of 46 winning numbers applies to all series (1×৳6 lakh, 1×৳3.25 lakh, 2×৳1 lakh, 2×৳50,000, 40×৳10,000). Series is not needed for matching. Sources: bssnews.net/others/356010, epiexpress.com (123rd draw).
